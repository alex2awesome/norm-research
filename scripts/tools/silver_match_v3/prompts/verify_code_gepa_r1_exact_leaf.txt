Code-review verifier: exact-leaf owner and consequence check

Before CONFIRM_MATCH, identify the human's requested change, its operational
object, and the stated consequence. The proposal must own all three more
specifically than every visible sibling. A topical or lexically similar card is
not enough. If the construct is clear but two bank leaves remain reasonable,
return AMBIGUOUS_MATCH rather than confirming either one.

Use these task-local boundaries:

- Removing unused state, parameters, branches, or ceremony is implementation
  simplicity. A catalogued structural smell/refactoring requires a broader
  behavior-preserving structural concern, not mere deletion.
- A direct Boolean or expression rewrite for readability is expression clarity.
  Broader needless design or unused machinery is implementation simplicity.
- Parameters, accepted values, defaults, return values, and the simple usage
  path concern API ergonomics. Exported type/constructor shape, stability, or
  safety concerns the public API surface.
- Keeping an implementation decision local or hidden is information hiding.
  Package/module/class layout and access-boundary organization concern code
  organization and visibility.
- Widespread call-site edits or failure to localize future change concern
  change localization. Reach-through and excess knowledge between collaborators
  concern coupling.
- Profiling, measured benefit, worst-case behavior, or an explicit performance
  safety trade-off concerns optimization discipline. Avoiding repeated work in
  an implementation concerns runtime/resource efficiency. Do not collapse
  either into broad correctness merely because a bug is possible.
- Testing observable public behavior rather than an implementation literal is
  behavior-focused testing. Runtime null/input/exception protection is
  defensive error handling. Generic missing tests do not uniquely distinguish
  the crowded test-design, strategy, coverage, and infrastructure leaves.
- A named linter, analyzer, formatter, auto-fixer, or CI enforcement mechanism
  concerns automated static enforcement. A convention without enforcement is
  style/standard compliance.
- A focused, reviewable PR without unrelated cleanup concerns atomic change-set
  scope. Correct commits, branches, merges, and traceability concern version
  control practice.
- Function parameters/returns/edge cases needing public documentation concern
  API documentation; a surprising local branch needing explanation concerns
  inline comment quality; broad project instructions concern general docs.

The evidence passage may resolve a referent, but do not import a neighboring
review point as the quoted statement's criterion. CONFIRM_MATCH at high
confidence only when the quote and stated consequence make the exact leaf
decisive. Otherwise choose the better supplied alternative or a typed
abstention.
