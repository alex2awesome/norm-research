Code-review leaf-precision addendum (GEPA round 1)

The evidence passage can contain several separate review points. Match only the
criterion expressed by the quoted HUMAN STATEMENT. Use surrounding text to
resolve its referent and meaning, not to substitute a neighboring suggestion
for the quoted one.

This bank deliberately contains overlapping leaves. High-confidence MATCH
requires an expressed clause that distinguishes the chosen leaf from every
visible sibling. A card being the most plausible of several broad cards is not
enough. When the words support a construct but not the bank's finer leaf
boundary, return MATCH_FAMILY_ONLY. In particular, be conservative with these
crowded families:

- formatting/style/conventions (including a41/a72/a109 and a21/a40/a64/a71/a110/a111);
- naming (a43/a70/a108);
- test design/strategy/adequacy (a10/a38/a39/a87/a88/a104/a128);
- comments and documentation (a15/a50/a52/a77/a115/a121);
- API quality and evolution (a11/a44/a83/a84/a106/a119);
- error handling (a30/a69/a76/a90/a119);
- broad maintainability, refactoring, and design leaves;
- broad efficiency leaves (a7/a48/a97).

Use the operational object to break a tie only when the human actually states
it. Examples:

- Public function/class behavior, parameters, return values, or edge cases
  needing docstrings/documentation can select public-API documentation. An
  inline request to explain a surprising local branch selects comment quality.
  General project docs select general documentation. Otherwise abstain at the
  family level.
- A concrete runtime/data-type/edge-case failure is functional correctness even
  if the reviewer also says an alternative is conventional. A pure idiom or
  style-guide request with no behavioral consequence is conventions.
- Moving an invariant operation such as regex compilation out of a loop is
  implementation efficiency. Profiling, measured bottlenecks, and explicit
  time/space trade-offs select performance-analysis/optimization leaves.
- A request to split a compound function selects function decomposition. A
  complaint specifically about nested branches or excess decision points
  selects control-flow complexity. Generic "too complicated" does not decide
  between them.
- A request for visible table-test data or one focused test concern may select
  test-design quality. Generic missing test coverage or an unexercised behavior
  usually does not distinguish the many testing leaves; use family-only unless
  a unique definition clause is explicit.

Do not treat confidence as a formality. Use high only when the exact leaf is
textually decisive after the sibling contrast. If a reasonable expert could
choose another visible sibling from the same words, use MATCH_FAMILY_ONLY,
normally with high confidence in that abstention.
