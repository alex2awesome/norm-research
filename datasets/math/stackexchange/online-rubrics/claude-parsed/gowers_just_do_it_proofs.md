# Just-Do-It Proofs — Tim Gowers (Gowers's Weblog, 2008)

A blog post articulating a recurring proof-style criterion: when does a proof reduce to "just doing the obvious thing" vs. require ingenuity?

## Core Characteristic
A "just-do-it" proof builds a sequence a₁, a₂, … satisfying constraints P₁, P₂, …, where at each stage "it is not hard to prove that there exists a_{n+1}" satisfying the next constraint.

## Distinguishing Features
1. **Constraints can be reformulated as a countable sequence.** Each step is a single requirement.
2. **Each inductive step avoids only finitely many obstacles**, while the search space (e.g. an open disc, an uncountable set) is much larger.
3. **The search space vastly exceeds restrictions**, so wiggle room is always available.

## When the Method Fails
- "Constraints are just too global" — e.g. constructing Hadamard matrices, where algebraic constraints couple the choices.
- Algebraic / global constraints prevent the inductive freedom required.

## Writing Implications
1. **Prefer sequential construction over simultaneous specification.**
2. **Prefer explicit procedures over implicit descriptions** when the problem admits it.
3. **Reformulate problems to expose countability.**
4. **Use straightforward induction** to prove feasibility at each stage.
5. **Recognize and label** the "just-do-it" pattern when it applies; reserve ingenuity for genuinely global problems.

## Implicit Aesthetic
"Elementary thinking" — prioritising accessibility and procedural transparency over ingenuity — is itself a virtue worth naming.
