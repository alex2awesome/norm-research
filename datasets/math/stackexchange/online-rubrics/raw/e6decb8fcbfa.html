Mathematical Proofs: How to Understand and Write Them

Introduction

This FAQ is about proofs. Proofs are central to mathematics, and writing proofs is a skill many people find hard to master. There are two separate skills to develop: finding the proof and communicating the proof. This article focuses on finding proofs, but it also gives guidance on communicating proofs clearly.

What is a proof?

A proof is a convincing explanation of why a mathematical statement is true. A valid proof may use only definitions, axioms, and previously proven theorems or lemmas. By nature, a proof uses deductive reasoning rather than empirical arguments.

For example, you cannot prove that [itex]n^2-n+41[/itex] is prime for all natural numbers n by checking a few cases; a proof must show why the claim holds for every possible n with no exception.

In logic we sometimes work with “formal proofs”: proofs with a very rigid symbolic structure and little or no natural language. Formal proofs are difficult to read; in practice mathematicians write informal proofs that are readable yet rigorous enough. Every good informal proof can, in principle, be converted into a formal proof — although this conversion is rarely practical. See http://us.metamath.org/ for many formal proofs.

Why bother with proofs?

Why not follow experimental sciences, checking many cases and concluding from the pattern? That reasoning is inadequate in mathematics. We want statements that are true for all cases, or false — not merely “usually true.” A result that holds for most cases is typically uninteresting unless “most” is defined rigorously.

For instance, the polynomial [itex]n^2-n+41[/itex] produces primes for many small n:

  • n = 1 → [itex]41[/itex]
  • n = 2 → [itex]43[/itex]
  • n = 3 → [itex]47[/itex]
  • n = 4 → [itex]53[/itex]
  • n = 5 → [itex]61[/itex]
  • n = 6 → [itex]71[/itex]
  • n = 7 → [itex]83[/itex]
  • n = 8 → [itex]97[/itex]
  • n = 9 → [itex]113[/itex]
  • n = 10 → [itex]131[/itex]

Checking many cases might suggest the polynomial is always prime, but the claim fails at n = 41, because

[tex]41^2 – 41 + 41 = 41^2.[/tex>

So experimental evidence can be misleading; proofs are required for certainty.

Methods of proof

There are several common proof techniques. Experience helps decide which method fits a given problem. Below are the main methods with examples.

Direct proof

A direct proof starts from the assumptions and proceeds logically to the conclusion.

Example: prove the square of an odd integer is odd.

An odd integer has the form [itex]2n+1[/itex]. Squaring gives

[itex](2n+1)^2 = 4n^2 + 4n + 1 = 2(2n^2 + 2n) + 1.[/itex]

This equals [itex]2m+1[/itex] with [itex]m = 2n^2 + 2n[/itex], so the square is odd.

Another direct example: for the linear polynomial [itex]aX + b[/itex] with [itex]a \neq 0[/itex], show [itex]\frac{-b}{a}[/itex] is a root:

[tex] a\left(\frac{-b}{a}\right) + b = \frac{-ba}{a} + b = -b + b = 0. [/tex]

Proof by contradiction

To prove a statement, assume its negation and derive a contradiction. This shows the original statement must be true.

Example (converse of the previous result): if [itex]n^2[/itex] is odd, then n is odd.

Assume for contradiction that n is even: n = 2k. Then

[itex]n^2 = (2k)^2 = 4k^2 = 2(2k^2),[/itex]

so [itex]n^2[/itex] is even, contradicting the assumption that [itex]n^2[/itex] is odd. Thus n must be odd.

Proofs by contradiction are common in everyday reasoning. For example, in a 2×2 mini sudoku where you must place the numbers 1 and 2 in each row and column, if the first row already has a 1, you cannot place another 1 in that row; assuming you could leads to a contradiction, so you must place 2.

Proof by induction

Induction proves statements for all natural numbers (or for all integers ≥ a base value) using a domino-like argument: show a base case and an implication from n to n+1.

Formally, prove two things:

  • The statement holds for a specific base value a (base case).
  • For each n ≥ a, if the statement holds for n then it holds for n+1 (induction step).

Then the statement holds for all integers ≥ a.

Example: prove [itex]1+2+3+\dots + n = \frac{n(n+1)}{2}[/itex].

  • Base case: n = 1 gives 1 = 1(1+1)/2.
  • Induction step: assume the formula holds for n. Then

[tex] 1+2+\dots + n + (n+1) = \frac{n(n+1)}{2} + (n+1) = \frac{n^2+n + 2n + 2}{2} = \frac{(n+1)(n+2)}{2}, [/tex]

so it holds for n+1 as well.

Another example: Bernoulli’s inequality states [itex](1+x)^n \ge 1 + nx[/itex] for integer [itex]n \ge 0[/itex] and real [itex]x > -1[/itex].

  • Base case: n = 0 gives (1+x)^0 = 1 = 1 + 0·x.
  • Induction step: assume (1+x)^n ≥ 1 + nx. Multiply both sides by (1+x) ≥ 0 to get

[tex](1+x)^{n+1} \ge (1+nx)(1+x) = 1 + (n+1)x + x^2 \ge 1 + (n+1)x,[/tex]

since [itex]x^2 \ge 0[/itex].

How to write good proofs

Writing and communicating proofs is a learnable skill. Adjust the level of detail to your audience: high-school students need more explanation than research mathematicians.

Do not overload proofs with symbols alone. Use sentences to guide the reader through the logical steps; include calculations, but explain what each step accomplishes. Avoid heavy use of formal logic symbols like [itex]\Rightarrow[/itex] or [itex]\exists[/itex] without text. For example, the terse proof

[tex]n=2k+1 \Rightarrow n^2=(2k+1)^2=4k^2+4k+1 \Rightarrow \exists m: n^2=2m+1[/tex]

is correct but unfriendly. A clearer version is:

“Let n = 2k + 1. Then [itex]n^2 = (2k+1)^2 = 4k^2+4k+1 = 2(2k^2+2k) + 1, so [itex]n^2[/itex] has the form [itex]2m+1[/itex] with [itex]m = 2k^2+2k[/itex], hence it is odd.”

    For me the worst flaw in proof writing is when the writer does not explain their steps. For example the justification for getting from one line to the next may be a result that was observed briefly in passing 20 pages ago and has not been mentioned since, but the author doesn’t reference it so the reader is left feeling stupid because they don’t remember the result and can’t understand how the step is justified. A number of widely-used physics texts do this frequently and I think it’s very poor. This is one area where reading symbolic logic proofs can actually be easier than reading some more wordy mathematical ones, because it is a requirement of a symbolic logic proof that the justification of every line be formally stated.

    The reason that many authors omit such justification is that it’s a lot of work to insert all the correct references. But for every two minutes that an author saves herself by not locating and inserting the justification ref, she has cost her readers collectively dozens, maybe hundreds of hours (depending on how many readers there are!) racking their brains and leafing through the book trying to work out the justification.

    Numbering all non-trivial equations is one way to make it much easier to include such refs.

    Knuth et al suggest varying one’s words in order to avoid monotony. For instance one might alternate ‘so’, ‘hence’, ‘therefore’, ‘it follows that’. My practice in the past has been to do that but now I am questioning it. One doesn’t read maths proofs for the beauty of their prose (that’s what poetry and fiction are for) but to gain understanding, and unnecessarily varying the terms used seems to me to be more likely to detract from understanding than to support it. A problem that sometimes arises is that, in the search for synonyms, the writer ends up using a word that has alternative possible meanings, and hence introduces ambiguity into the text. This is a matter for judgement and I imagine that there’s a sweet spot somewhere between the extremes of always using the same word and avoiding using the same key word twice in a paragraph. Currently I find I’m steering away from variety towards greater consistency and clarity in word choice, relative to where I was.
