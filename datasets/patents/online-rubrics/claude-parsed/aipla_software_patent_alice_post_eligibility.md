# Software Patent Strategies Post-Alice

## Core Strategy: Demonstrate Inventive Concept

The key distinction: claims that reflect genuine improvements to technology (eligible) versus those that merely apply an abstract idea using generic computer components (ineligible).

## Practical Claim Drafting Approaches

### 1. Show Specific Technical Benefits
Name specific technical benefits in claims:
- Faster search times within a database
- Smaller memory requirements
- More dynamic information filtering
- More efficient information processing
- Reduced network bandwidth usage
- Improved security/encryption
- Improved error correction

### 2. Use Structured UI Approaches
Claims should require:
- A specific GUI structure
- A prescribed functionality directly related to the GUI structure
- Solving a specific user-interface problem

### 3. Focus on Hardware-Software Integration
- Frame the invention as a technological improvement
- State how the invention solves existing technical or industry problems
- Include details of computer architecture
- Software interaction with hardware (actuation, control)
- Hardware limitations (specific sensors, processors, memory architectures)

### 4. Avoid Pure Method Claims
- Tie methods to specific machines
- Include transformation of data into a different state
- Avoid claims that read on mental performance

## Eleven Tips for Software Patents

1. Identify the technical problem clearly in the specification
2. Describe the solution in technical terms (algorithms, data structures)
3. Include flow diagrams and pseudocode
4. Explain why the prior art was deficient
5. Quantify improvements (time, space, accuracy)
6. Draft claims that require specific computer architecture
7. Avoid mental-step language in independent claims
8. Include dependent claims with hardware specifics
9. Consider apparatus claims with structural detail
10. Draft Beauregard claims for software products (with non-transitory medium)
11. Include narrow fallback claims tied to specific technical effects

## Litigation Strategy

A patent owner defending against a § 101 challenge should:
- Identify technological innovations required by the claims
- Contend that the claims require more than generic software/computer elements
- Invoke specific Federal Circuit cases finding similar claims eligible
- Distinguish from cases finding similar claims ineligible

## Key Federal Circuit Cases (Software Eligibility)

- **DDR Holdings**: Look-and-feel of host site preserved in linked third-party site
- **Enfish**: Self-referential database table
- **McRO**: Specific rules for animation lip-sync
- **Berkheimer**: Inventive concept can be factual question
- **Cellspin Soft**: Pleading-stage challenges may fail
- **Trading Tech**: GUI for trading

## Examiner Variability

§101 rejections generally are not applied consistently between art units and examiners. Examiners may share thoughts on §101 rejections during interviews — use this opportunity.
