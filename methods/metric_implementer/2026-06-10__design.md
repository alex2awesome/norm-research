# metric_implementer — design (2026-06-10)

Concrete implementation design for the three components: §1 scorecard, §2 improvement
loop, §3 articulability scaling laws. Everything operates on the project-standard
`MetricSpec`-shaped object (`{metric_id, name, description, guidance/rubric, kind}`) and an
injectable `judge_scorer(metrics, texts) -> (levels, applicable)` so it works unchanged for
online-rubric metrics, infilling discoveries, autometrics output, etc.

---

## §1 The scorecard

```python
@dataclass
class BudgetSpec:                      # provenance: what resources produced this metric
    instruction_tokens: int            # rubric/definition length
    n_fewshots: int
    data_budget: int                   # labeled items available to optimizer/reconstructor
    judge_model: str                   # + numeric capability anchor (see §3)
    optimizer_rounds: int
    inference_passes: int              # ensemble k at scoring time

@dataclass
class MetricScorecard:
    metric_id: str
    budget: BudgetSpec
    # ---- construct fidelity (column 1: optimizable) ----
    reliability: float                 # test-retest rho, k passes, n_retest items
    reliability_by_region: dict        # optional: per tree-node / cluster
    cf_validity: float                 # acc on decorrelated counterfactual pairs (fresh batch)
    cf_by_suspect: dict[str, float]    # per named confound — the diagnostic detail
    reconstruction_semantic: float     # LLM-judged match: induced rule vs original rubric
    reconstruction_behavioral: float   # label agreement of re-implemented induced rule
    consistency: dict                  # paraphrase_stability, order_invariance,
                                       # monotonicity, format_robustness ∈ [0,1]
    silver_alignment: float | None     # agreement w/ naturally-occurring expert commentary
    # ---- evaluation only (column 2: NEVER in any optimizer objective) ----
    predictive_contribution: float     # held-out deviance drop / AUC delta when added
    coverage: float                    # population-weighted standardized effect
    # ---- classification (column 3: findings, not gates) ----
    metric_type: str                   # "transparent" | "instrument_tacit" (reliable+valid
                                       # +predictive but reconstruction-failing) | "unstable"
                                       # | "confounded" (fails CF for a named suspect) | ...
```

Per-measure protocols:

1. **Reliability** (`scorecard.py`): score `n_retest≈100` items k=3 times (temperature>0 or
   seed-varied); ρ = mean pairwise Pearson on applicable-in-all-passes items. Per-region
   variant takes a partition (tree leaves, clusters) and reports ρ per cell with n.
2. **Counterfactual validity** (`counterfactuals.py`):
   - `name_suspects(metric, labeled_sample, reconstructor) -> list[Suspect]` — run
     reconstruction first; every induced reading ≠ target is a named suspect S. Add
     standing suspects: length, sentiment, formality, topic.
   - `generate_pairs(metric, suspects, generator, n_per_cell)` — a 2×2 per suspect:
     (T+, S+), (T+, S−), (T−, S+), (T−, S−); minimal pairs, attribute planted by
     construction (generalizes the `metrics_tree_infilling/tests/test_scenario` world
     machinery into a library). Generator family ≠ judge family.
   - `cf_validity = P(judge tracks T across the pairs)`; `cf_by_suspect[S] = P(judge
     tracks T | S held fixed)` — a judge tracking S instead of T scores ~0.5 on exactly
     that cell, which localizes the confound.
3. **Reconstruction** (`reconstruct.py`): judge labels m≈200 real items; reconstructor
   (different family) gets stratified (text, score) pairs, returns `{description, rubric}`;
   semantic match = LLM-judged equivalence (5-point, two graders, different families);
   behavioral match = score the induced rubric on held-out items, agreement with the
   original judge. Report both — semantic-low/behavioral-high = "extensionally same,
   intensionally different description," its own interesting category.
4. **Consistency** (`consistency.py`): paraphrase k variants of each test item (meaning-
   preserving), measure score stability; shuffle document order where applicable; graded
   monotone edits (inject more/less of the attribute) → Kendall τ of scores vs edit grade.
5. **Silver alignment**: for tasks with expert commentary (peer reviews, agency responses,
   editorial notes): an extractor tags which texts the commentary explicitly invokes the
   criterion on (positive or negative); silver_alignment = agreement of the metric's level
   with the invoked polarity on that subset. Low-n, biased subset — report with n, never
   optimize against it (it is too gameable and too sparse; it stays column-2-adjacent).

**Cost note** (all scoring via offline-batch vLLM, thousands of prompts per `generate`
call): one scorecard ≈ k·100 (retest) + ~400 (CF) + 200 + 100 (recon label + behavioral)
+ ~300 (consistency) ≈ **1.3K judge calls** — minutes on a B200 per metric, batchable
across metrics.

## §2 The improvement loop (`optimizer.py`)

```
improve_metric(metric, corpus, cfg) -> (best_prompt, scorecard_history, findings)

P ← {π₀ = metric.guidance}                      # candidate pool
holdout ← freeze: real-item retest sample + eval items     # untouched until acceptance
for r in 1..cfg.rounds:                                    # default 6
    cf_r ← generate fresh counterfactual batch             # REGENERATED each round
    for π in P:  score fidelity(π) on cf_r + retest + recon + consistency   # NO predictive
    failures(π) ← textual artifacts:
        • CF pairs misjudged   (minimal pair + planted truth + suspect name)
        • induced rule when reconstruction mismatches      ("you are measuring S")
        • retest flips         (items scored differently across passes)
        • paraphrase instabilities (the variant pair that flipped)
    mutations ← reviser_llm(π_best, scorecard, failures) × cfg.n_mutations   # default 8
        mutation operators (reviser chooses, guided by which measure failed):
        CLARIFY     sharpen the attribute definition against the named suspect
        FEWSHOT+    inject a failed CF pair as a worked example (known answer!)
        ANCHOR      tighten level descriptions (what exactly is a 0.5?)
        EDGE        add an explicit edge-case clause from a retest-flip item
        PRUNE       remove text that correlates with instability (shorter ≠ worse)
        DECOMPOSE   split into sub-questions + aggregation rule (raises structural
                    complexity — budget-tracked, see §3 axis 7)
    P ← top-K by scalarized fidelity (K=4)
acceptance (one shot, frozen holdout):
    fresh CF batch from a DIFFERENT generator family
    fresh reconstructor from a DIFFERENT family
    accept π* iff scalarized fidelity(π*) > fidelity(π₀) on holdout
    REPORT predictive_contribution(π₀) vs (π*) — finding either way:
        fidelity↑ prediction↑  → the prompt was genuinely noisy/confounded
        fidelity↑ prediction↓  → π₀ predicted via a confound; quantified deconfounding
```

Objective scalarization (config, defaults): hard floor ρ ≥ 0.7, then
`0.40·cf_validity + 0.30·reconstruction_behavioral + 0.20·ρ + 0.10·consistency_mean`.
Silver alignment and predictive contribution are excluded by construction (not by
convention — `fidelity()` simply cannot see those fields).

Anti-Goodhart invariants (assert in code, not just docs):
- counterfactual batches are round-scoped; no candidate is ever scored twice on one batch;
- generator / reconstructor / judge are distinct model families at acceptance;
- the eval split for predictive contribution is never readable by the optimizer process.

Cost: rounds(6) × candidates(8) × ~700 calls ≈ **35K judge calls per metric** — one
offline-batch evening for a few dozen metrics; the reviser uses ~50 Claude calls/metric
(Max-plan subagents).

## §3 Articulability scaling laws

### The estimand: the frontier, not the average

`fidelity*(m; B) = max over articulations of m costing ≤ B` — operationalized by running
the §2 optimizer under a **budget cap** B and taking its best accepted candidate. This is
the move that fixes the earlier noisy attempts: at fixed budget, prompt *content* variance
swamps any budget trend, so mean-over-prompts curves are flat and noisy. The frontier is
what the articulability question actually asks ("CAN it be articulated with this much X"),
and it is monotone in B by construction (max over ≤ B).

### Why the earlier attempt didn't show clean scaling — diagnosis → fix

| Failure mode | Fix |
|---|---|
| Measured mean-of-prompts at each length (padding ≠ articulation effort) | measure the optimizer-frontier at each budget cap; multiple optimizer seeds, report best + bootstrap CI of the max |
| Pooled metrics with heterogeneous saturation points → flat average curves | fit per-metric curves first; aggregate as survival/mixture (below) |
| Raw AUC/agreement y-axis: ceiling compression + judge-noise attenuation | y = disattenuated, normalized fidelity `(achieved − chance)/(ceiling − chance)`; plot vs log B |
| Axes confounded (a better model also uses prompts better) | factorial grid from a center point; model axis numerically anchored; report interactions |
| Non-nested data samples → curves jitter from sampling, not budget | nested subsets D₁⊂D₂⊂D₃ (and nested few-shot pools); same frozen eval set at every point |
| One seed per cell | ≥3 optimizer seeds per (metric × budget) cell; paired bootstrap over eval items for any "B₂ > B₁" claim |

### Headline analysis: articulation as survival

For each metric define **budget-to-articulation** `B*(m) = min B : fidelity*(m;B) ≥ τ`
(τ e.g. normalized 0.8 *and* cf_validity ≥ 0.9). Metrics not reaching τ at the max tested
budget are **right-censored** — "not yet articulated," never "tacit, period." Then:

- **Kaplan–Meier curve per axis**: fraction of the metric population articulated vs budget.
  This *is* "the space of metrics that CAN be articulated with more X," with honest
  uncertainty and honest censoring. One curve per axis = which resource buys articulation.
- **Per-metric curve classification**: fit a saturating form (logistic in log B) per metric
  and label each {**articulated** (reached τ), **climbing** (censored, positive slope at
  B_max — more budget would plausibly get there), **resistant** (plateaued below τ across
  *all* axes, below the dense ceiling)}. *Resistant-everywhere + dense-learnable* is the
  strongest constructible evidence of tacitness — and falsifiable by extending any axis.
- **Cox-style regression** of B* on metric properties (task, coverage, abstraction type,
  thin/thick) → *what predicts being hard to articulate* — a paper result on its own.

### How this dissolves the circularity

The reconstruction-bottleneck objection ("your instrument check presupposes articulability")
becomes a measured curve instead of an assumption: ceiling claims are stated as "fidelity
frontier flat in all axes at slope ≈ 0, gap to dense ceiling = Δ," which is (a) relative to
explicit, extendable operationalizations and (b) empirically falsifiable. We never claim a
metric can't be articulated; we report where it sits on the frontier and what it would take
to move it.

### Axes

| # | Axis | Knob | Notes |
|---|---|---|---|
| 1 | Instruction length | token cap on rubric/definitions | the *description* half of prompt length |
| 2 | Few-shot count | n worked examples | the *demonstration* half — scale separately from 1 |
| 3 | Labeled-data budget | items available to optimizer + reconstructor (nested) | the user's "data" axis: data enters as *evidence* — more contrastive/reconstructive examples, bigger few-shot pool |
| 4 | Model capability | judge tier AND optimizer/reconstructor tier — **vary separately** | anchor each model to a numeric score (held-out general benchmark) so x is quantitative; "judge-limited vs articulation-limited" is itself a finding |
| 5 | Inference-time compute | ensemble k, thinking/CoT budget, self-consistency votes | cheapest axis; turns one judge into a ladder |
| 6 | Optimizer effort | GEPA rounds R | articulation *search* effort, distinct from artifact size |
| 7 | Structural complexity | rubric clause count / DECOMPOSE depth / distilled-program AST size | the **thin-vs-thick rules axis** made quantitative — most theoretically loaded; connects to Daston + legal rules-vs-standards |
| 8 | Interaction order | rubric may reference 1 attribute / pairwise / k-way combinations | probes the §9 XOR-style limit |

Cross-axis analysis: **iso-fidelity contours** (Chinchilla-style) — at fixed total token
budget, the optimal instruction/few-shot split; whether data substitutes for model
capability (exchange rates between axes). "Articulation-optimal budget allocation" is a
deliverable: it tells every other pipeline in the project how to spend.

### Minimal viable experiment (first run)

- 1 task (peer-review), ~20 metrics spanning the coverage range, axes 1+2+5 only
  (all cheap), 3 budget points each, 3 seeds, frozen eval set.
- Deliverables: per-metric frontier curves, the first KM curve, and the
  articulated/climbing/resistant triage — enough to validate the protocol before paying
  for axes 3–4.

## §4 Record-keeping system (implemented 2026-06-11, `registry.py`)

Every artifact, every revision, every measurement — immutable and append-only. Layout under
`outputs/metric_implementer/<task>/registry/`:

```
ledger.jsonl                                  # append-only event log (one JSON/line)
metrics/<metric_id>/
    metric.json                               # identity: id, name, description
    versions/v000__prompt.json                # immutable version records, per KIND
    versions/v000__code.json                  #   (prompt and code tracked in parallel)
    scorecards/<vid>__<kind>__<evalhash>.json # scorecard per (version × eval config)
    disagreements/<vid>__code_vs_judge.json   # cross-implementation disagreement queues
    HEAD.json                                 # current accepted version per kind
```

**Version record** = the scaling-law row, measured at creation time (never hand-entered):

| Field group | Contents |
|---|---|
| artifact | full body + sha256 hash, kind (prompt/code), declared invariances |
| complexity (auto) | prompt: instruction_tokens, clause_count, n_fewshots; code: LOC, AST nodes, cyclomatic, function count (`artifact.py`) |
| data budget | count + content-hash of the item ids visible to the optimizer when this version was produced |
| caps in force | the BudgetCaps active during creation (the scaling cell it belongs to) |
| models | judge / reviser / reconstructor used |
| lineage | parent version, operator (INIT/CLARIFY/FEWSHOT+/ANCHOR/EDGE/PRUNE/DECOMPOSE/CODE_REVISE), run id, optimizer round |

**Ledger events**: METRIC_REGISTERED, VERSION_CREATED, VERSION_REJECTED_BUDGET (cap
violations are logged, not silently dropped), SCORECARD_COMPUTED, ACCEPTED, RUN_STARTED,
RUN_FINISHED (with per-role call counts, token counts, and **dollar cost** — OpenRouter
reports `usage.cost` per call and `backends.py` accumulates it, so spend is part of the
experimental record).

Nothing is ever rewritten: re-running adds events. The scaling analysis is a pure read over
`versions/*` + `scorecards/*` — every point on a frontier curve is reconstructible to the
exact artifact text, the data it saw, the caps it ran under, and what it cost.

## §6 Strong-proposer / weak-judge engineering (2026-06-11; user: "that is literally our setup")

The asymmetry is the judge-capability scaling axis made operational — optimizing at a fixed
weak judge tier yields one frontier point; sweeping `--judge-models` traces the curve.

- **Oracle agreement** (new fidelity component, w=0.25): a strong model
  (`anthropic/claude-sonnet-4.5` via the same OpenRouter key) scores the metric's canonical
  *description* (NOT the candidate body — a fixed target that doesn't move as candidates
  mutate) once per metric (cached); component = Spearman(weak-judge-with-candidate-prompt,
  oracle). Instrument-vs-instrument → still construct fidelity, the invariant holds. The
  oracle itself gets counterfactually validated; oracle-agreement is one component among
  several so its confounds aren't inherited wholesale.
- **Failure attribution**: the strong reviser tags each counterfactual miss
  `AMBIGUOUS_PROMPT` (rubric's fault → CLARIFY/ANCHOR/EDGE) vs `JUDGE_LIMITATION` (needs
  judgment the rubric can't transmit to a weak reader → DECOMPOSE/MECHANIZE).
- **MECHANIZE operator**: judgment-language → explicit step-by-step checks + aggregation
  rule. Code is the limit of mechanization: prompt → mechanized prompt → `score(text)` is
  ONE thinning axis, unifying the two artifact kinds.
- **Thickness readout**: min judge tier at which the optimized articulation reaches τ =
  per-metric thin/thick measurement (Daston operationalized); judge tier is a grid
  dimension in `run_trial scaling --judge-models ...`.

## §7 First trial results (2026-06-11, 60 items, Llama-8B judge, total cost $0.044)

| metric | kind | fidelity | ρ | CF | recon_b | consist | code↔judge ρ |
|---|---|---|---|---|---|---|---|
| identifier_quality | prompt | 0.53 | 0.32 | 0.56 | 0.61 | 0.63 | 0.06 |
| identifier_quality | code | 0.71 | 1.0 | 0.81 | 0.29 | 1.0 | — |
| explanatory_comments | prompt | 0.39 | 0.22 | 0.50 | 0.38 | 0.33 | 0.20 |
| explanatory_comments | code | 0.50 | 1.0 | 0.50 | −0.05 | 1.0 | — |
| edge_case_handling | prompt | 0.28 | 0.13 | 0.38 | 0.18 | 0.5 | −0.06 |
| edge_case_handling | code | 0.57 | 1.0 | 0.38 | 0.39 | 1.0 | — |

Findings: (1) 8B judge test-retest reliability is very poor (0.13–0.32 @ temp 0.7) — the
optimizer's primary headroom; (2) code↔judge convergence ≈ 0 — the two implementations of
the same metric currently measure nearly unrelated things (measure 8's disagreement queues,
persisted in the registry, are the improvement queue); (3) all six scorecards + versions +
ledger live under `outputs/metric_implementer/code-review/registry/`.

**First live GEPA run** (edge_case_handling/prompt, 2 rounds, $0.30): seed 0.283 → best
in-loop 0.400, acceptance 0.327 → 0.374, **accepted=False** — correctly. The winning
mutation (MECHANIZE) raised reconstruction 0.19→0.67 via the *simplification channel* while
reliability collapsed to ≈0 (the predicted lawful-looking-but-unstable attractor); the
ρ ≥ 0.5 promotion floor blocked it. A second mode appeared: near-constant judge (ρ=0.47,
recon=NaN). Fixes landed: (a) degenerate-constant judge now scores recon=0 instead of NaN
(renormalizing NaN away would reward collapsing the judge); (b) reliability estimation
3 passes × 32 items (2×24 gave ρ swings −0.01..0.47 across sibling candidates — too noisy
to rank mutations). Observation to watch: all 6 mutations chose MECHANIZE (attribution
routed everything to JUDGE_LIMITATION — plausible at ρ=0.13, but operator diversity needs
monitoring). Reconstruction-ceiling check confirmed: observed recon_b ≈ √ρ per metric →
reconstruction is currently reliability-limited; expect recon_b to rise iff ρ rises, with
recon_semantic (NOT in the objective) as the free check that it rose for the right reason.

## §8 The equivalence-frontier descent (2026-06-11, user design — likely the paper experiment)

Question it answers: where does the scoring decision live — in the words or in the reader?
(The V–A / thin–thick coordinate of a metric, measured.)

- **Anchor** = strong judge + rich rubric = the reference construct (CF-validated itself,
  never treated as truth — the claim is construct *preservation*, not correctness).
- **Descent**: for each judge tier (descending), GEPA-optimize the rubric with the
  objective dominated by agreement-with-anchor (repoint the oracle component from the
  canonical description to the anchor's cached scores; sweep `--judge-models`).
- **Readouts**: (1) frontier curve = best agreement-with-anchor per tier; (2) the
  fuzzy→mechanized artifact sequence, each version in the registry with complexity;
  (3) **mechanization floor** = tier below which no rewrite preserves the construct —
  the metric's thickness in judge-capability units.
- **Intrinsic-measure validation**: score every artifact in the sequence with (a) the
  clause-decidability profile (string-match < syntactic < executable < shallow-semantic <
  deep-semantic < community-membership — the 9-type taxonomy applied inside one metric)
  and (b) AST-saturation of code↔judge convergence. Test: do profiles shift down-ladder
  along the descent, and does the SEED's profile PREDICT its floor? If yes → thickness is
  readable off the definition without running the descent.
- **Definition-ablation 2×2** (cheap companion): {weak,strong} × {name-stub, full rubric}
  → words effect / reader effect / interaction. Interaction = Daston's thick rule written
  down (stated, but execution needs a strong reader). corr(strong+full, strong+stub) ≈ 1 =
  the words are a pointer into the reader's prior = the A/dense boundary.
- Cautions wired in: extensional-match-intensional-mismatch (reconstruction stays as
  check); anchor-quirk overfitting (frozen holdout, fresh CF); detail can HURT weak models
  (frontier search includes PRUNE); ρ floor per tier or agreement is noise-matching.
- Prior art: TWO-STAGE CHECK. Stage 1 (2026-06-11, 7 inline search angles + 2 direct paper
  reads); Stage 2 (same day, **5 parallel Sonnet subagents** sweeping LLM-judge, education
  measurement, expert systems/economics-of-codification, ML scaling theory, and
  annotation/perspectivism — ~250 tool calls total, fetch-and-verify on every threatening
  candidate). **VERDICT: zero kills across all literatures.** Every field has the
  components; none does the inversion (frontier → floor → construct measurement).

  **Nearest neighbors by literature (the related-work section, with differentiators):**
  1. **Alur et al. 2023/2024 (NeurIPS, arXiv 2306.01646 + 2402.00793) — closest formal
     analog anywhere.** Statistical test for irreducible expert signal beyond what any
     algorithm extracts (~30% of ED/radiology cases). Differentiators: opposite direction
     (expert-beats-algorithm, not rules-capture-expert); REQUIRES outcome ground truth
     (our floor is label-free); no executor-capability axis; framed as "should we
     automate," not criterion measurement.
  2. **LLM-judge:** GER-Eval (2602.08672) — linguistic criteria transfer across judges,
     factual collapse on weak ones (the diagnostic version of component (d); reviewers will
     ask "why not just systematic GER-Eval?" → answer: they observe fixed-rubric transfer
     failure; we optimize per tier and invert the floor). CheckEval (+0.45 agreement =
     feasibility evidence). IRT-for-judges (2602.00521) — judge-ability × item-difficulty
     formalism, applied to responses not criteria (borrow the formalism for the floor).
     HtT concept distillation (2408.09365) — the descent's mechanism, engineering framing.
  3. **Education measurement (humans):** Sadler 2009 (indeterminacy of preset criteria) +
     Lumley 2002 (scales "do not cover all eventualities," think-aloud) + Wolfe 1998
     (experts interpret rubrics via internalized values) = the floor EXISTS on humans,
     theoretically argued, never measured. Jonsson & Svingby 2007: analytic rubrics make
     novices behave more like experts (partial component (a)). Nobody ran the 2×2 or
     measured the floor; LLMs are the enabling technology (can't run 50 revisions × 4
     tiers × 3 seeds on human raters).
  4. **Economics of codification:** Cowan 2001 (qualitative domain-codifiability typology);
     Zander & Kogut 1995 (codifiability by SURVEY — "can a manual be written?");
     Szulanski 1996 (causal-ambiguity scale); Cowan/David/Foray 2000 (tacitness =
     codification cost). Labor econ: ALM 2003 routine/non-routine, Autor 2014 Polanyi's
     Paradox, Brynjolfsson-Mitchell SML rubric, Eloundou 2023, Schaal 2025 (LLM-annotated
     "tacit knowledge intensity"). ALL measure codifiability by ANNOTATION/SURVEY —
     "economists score tacitness by asking; we score it by trying."
  5. **ML theory:** weak-to-strong (Burns 2312.09390; Pawelczyk 2501.00418 — privacy
     doesn't transfer = per-property floor via FINE-TUNING, not language); "Quantifying
     Elicitation" (NeurIPS 2025) — logistic elicitation-cost curve with trainable-params
     as x-axis (right shape, wrong axis); DETAIL Matters (2512.02246) — 2 models × 3 fixed
     levels, a 1-D slice.
  6. **Annotation science:** SILICON (2412.14461) — guideline-induced vs model-induced
     error decomposition (closest to words-vs-reader; treats them as confounds to remove);
     instructions-RCT (PMC12668505) — detailed instructions LOWERED crowdworker agreement,
     some categories instruction-resistant (human evidence for non-monotonicity + resistant
     criteria); Codebook LLMs (Political Analysis) — small models follow label semantics,
     ignore codebook detail (the "name = pointer into reader's prior" phenomenon in the
     wild).
  7. **Deep lineage (motivation section):** Meehl→Dawes/Faust/Meehl 1989→Grove 2000
     (clinical-vs-actuarial: one fixed mechanization vs experts); Shanteau 1992 (task
     characteristics determine whether expertise is reliable); Yu 1979 (MYCIN vs experts —
     rule-base performance measured, framed as system eval); Bouaud 2009 (44.8% of patients
     outside guideline rules — a one-domain rule-residual); Chao & Salvendy 1994 (% of
     expert knowledge elicited vs #experts); Kalyuga expertise-reversal (same rules,
     different executor → different performance; explicit guidance HURTS experts);
     Dreyfus & Dreyfus 1986. Also for the triage ladder: Boguslav & Cohen 2017 + Richie
     2022 (is IAA a ceiling on model performance — cite for the twin-ceiling rung).

  **The unclaimed combination (verified across all five literatures):** (i) instruction
  optimization (not fine-tuning) as the transfer mechanism; (ii) per-tier best-achievable
  agreement as the frontier; (iii) the floor as a label-free measurement of the criterion's
  tacitness/rules-vs-standards position; (iv) survival analysis over a criterion bank.
  Caveats: web/English, one day, current review cycles may hold submissions → re-sweep at
  paper time; watch citation graphs of CheckEval, HtT, Alur et al., GER-Eval.

## §9 Triad layer (2026-06-11): item difficulty, judge quality, words-vs-reader

The lit review's structural lesson (CrowdTruth + Generalizability Theory, the
rater-cognition lineage) implemented as `triad.py` + `run_trial triad`. Judge config ≈
worker, datapoint ≈ unit, metric ≈ annotation task; all of it CALIBRATE-channel
(label-free).

**New scorecard-adjacent measures** (from the review; computed per metric version ×
judge panel from one pooled long table):

1. **UQS per item** (CrowdTruth fixed point over scalar scores, agreement = 1−|a−b|;
   WQS-weighted so disagreement on ambiguous items isn't punished) → the difficulty
   profile. Terciles → hard/mid/easy strata.
2. **WQS per judge config** — including the anchor. *The anchor is a measured worker,
   never an assumed oracle*: low anchor-WQS on a criterion flags it for known-answer
   audit before its floor is trusted.
3. **Variance components** (G-study: item / judge / item×judge / pass-residual; judge
   facet = model, passes = replicates) → **words_share = σ²_item/(σ²_item+σ²_int)**, a
   definition-intrinsic thin/thick index: thin criteria put construct variance in the
   item main effect (the words decide), thick in the interaction (the reader decides).
   Judge main effect = leniency — calibratable, not thickness.
4. **D-study** Eρ²(n_judges, n_passes) — the principled replacement for hand-picking
   reliability passes×items.

**Datapoint selection policy** (answers "easiest with most agreement?"): a **mixture,
never easiest-first** — easiest-first inflates fidelity and hides the floor;
hardest-only biases every estimate. `stratified_order(ids, uqs, frac_hard=0.6)` puts a
hard-oversampled mixture at the head of the list, which is where every head-of-list
consumer (oracle subsample, CF bases, consistency, reconstruction shown-pairs) draws
from. Difficulty is a **conditioning variable, not a budget axis**: you don't spend it,
you measure the frontier *at* it — fidelity\*(m; B | stratum). The mechanization floor
on the hard stratum is the real floor; easy-item agreement is where
lawful-looking-but-wrong rubrics hide. (GEPA integration: pass a stratified ordering as
`texts` and per-instance Pareto retention then keeps candidates that win on different
strata — difficulty becomes the Pareto dimension.)

**First live panel** (edge_case_handling/prompt v008, 30 items, {8B, 70B, Qwen-72B}×3
passes + Sonnet anchor ×1; $0.157, 82 s, parse-fail 2.7%):

| readout | value | meaning |
|---|---|---|
| words_share | **0.75** | mostly thin; ~25% of construct variance is reader-dependent |
| σ² residual share | 0.32 | pass noise is huge → single-pass judging is ~coin-flip |
| D-study Eρ² | 1j×1p **0.51** → 3j×3p **0.84** → 5j×3p 0.90 | score with panel means, not single judges |
| WQS | qwen .875 > 70B .846 > 8B .790 > **anchor .775** | Sonnet diverges from the open-panel consensus — measured, not assumed |
| anchor Spearman, overall→hard | 8B .69→**.40**, 70B .78→.66, qwen .78→.61 | capability gap concentrates on hard items; tier ordering emerges only there |

Two design consequences adopted: (a) reliability estimation should move from
single-judge passes to small-panel means with D-study-chosen allocation; (b) every
scorecard's oracle subsample switches to `stratified_order` (≈⅔ hard + ⅓ backbone).

## Build order

1. `scorecard.py` + `reconstruct.py` + `counterfactuals.py` (the measures) — these are
   immediately useful to *every* pipeline, before any optimization exists.
2. `consistency.py` (cheap probes).
3. `optimizer.py` (§2 loop) on 2–3 deliberately weak rubrics — verify fidelity gains are
   real on the cross-family holdout.
4. `scaling.py` + the minimal viable experiment (§3).
5. Wire as consumer APIs: `metrics_tree_infilling` calls `compute_scorecard` on discovered
   features; autometrics/metric_tree likewise; scorecards accumulate in one ledger per task.
